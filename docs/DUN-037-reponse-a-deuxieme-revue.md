## Choix et conséquences pour les données existantes

- Les nouveaux rappels sont retrouvés par leur métadonnée **native**, même si le processus s'arrête avant de recevoir ou de stocker leur ID. La clé historique `scheduledReminderIds` reste lue pendant la transition ; ses IDs ne sont supprimés qu'après une annulation réussie. Les autres notifications programmées restent intactes.
- Le nettoyage à la déconnexion peut retirer un ancien rappel dont le propriétaire n'était pas enregistré, puis le compte actif reprogramme ses rappels depuis son profil. Si le profil n'est pas disponible, la programmation attend sa prochaine lecture réussie ; si une programmation échoue après avoir commencé, son marqueur local reste en attente pour la reprise.
- Aucune migration Supabase, suppression de tâche/tag existant ou modification de données de production n'a été faite. Les adaptateurs Supabase restent transitoires jusqu'à DUN-048. Les opérations entre appareils restent un risque explicite.
