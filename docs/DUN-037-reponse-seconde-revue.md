# DUN-037 — Réponse à la revue indépendante et points à revérifier

Date : 26 septembre 2026. Ce document décrit les corrections locales faites **après** la première revue (`/private/tmp/DUN-037-revue-independante.md`). Il ne vaut ni validation de DUN-037 ni autorisation de push. La case DUN-037 a été rouverte dans `ROADMAP.md`.

## Périmètre et critère

Le critère de sortie de DUN-037 est : les écrans d'accueil, Box, Daily et réglages, ainsi que leurs composants, passent par des dépôts pour les données métier ; un échec ne laisse pas une réussite seulement affichée. Les adaptateurs sont encore Supabase. SQLite et ses migrations relèvent de DUN-048. Les opérations composées durables, notamment le réordonnancement, relèvent de DUN-008. Aucun service de production n'a été modifié pendant les corrections.

## Choix discutés et points non résolus

- **Tous les constats de la première revue ont été examinés.** Ceux sur la perte de tags, l'état du popup, les rappels, l'identité et l'affichage ont reçu un correctif local. Les transactions demandées pour les changements de tags, la création avec tags et le réordonnancement n'ont pas été présentées comme résolues par une simple compensation.
- **Réordonnancement : report assumé à DUN-008.** Ajouter une transaction SQL isolée à ce lot d'interfaces aurait étendu son périmètre sans régler le futur stockage SQLite. Le défaut reste un risque connu et doit bloquer toute affirmation de parcours entièrement fiable.
- **Concurrence entre appareils et interruptions brutales : non résolues.** La file de promesses protège seulement les écritures concurrentes dans une instance de l'app. Une migration/RPC transactionnelle ou un mécanisme de reprise durable reste à concevoir et à tester sur une base de test.
- **Rappels : reprise partielle, à auditer.** Le marqueur local est lié à l'utilisateur, mais les IDs des notifications programmées sont stockés sous une clé globale à l'appareil. Le reviewer doit examiner les courses entre les appels de l'accueil, de l'entrée de l'app et des réglages, ainsi que les changements de compte et les interruptions entre chaque opération iOS/AsyncStorage.
- **Restauration visuelle après un échec partiel : à valider.** La relecture du popup est codée, mais aucun test d'interface n'a prouvé l'état des champs et du sélecteur dans tous les interleavings.
